## Unternehmensgedächtnis – 2026-11-06 (Selbstprüfung beim Bau)

| Thema                          | Maßnahme                                                                                                                                                                         |
| ------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Falsche „Fakten“ durch Agenten | Vorschläge (`status = 'proposed'`) sind nicht durchsuchbar und werden nicht indiziert; nur Personen mit `knowledge.manage` übernehmen sie (Server-Prüfung in jeder Aktion)       |
| Zugangsdaten im Gedächtnis     | `redactCredentials` vor dem Speichern von Vorschlägen und beim Bearbeiten von Gedächtnis-Einträgen                                                                               |
| Speicher-/Prüf-Flut            | höchstens 100 offene Vorschläge pro Firma, 4.000 Zeichen pro Eintrag, 100.000 pro Artikel, Verfall unbearbeiteter Vorschläge nach 60 Tagen                                       |
| Mandantentrennung              | alle Zugriffe über `withTenant` + RLS; Bestätigen/Verwerfen/Export fremder IDs liefert „nicht gefunden“ (Integrationstests)                                                      |
| Massenabfluss per Export       | Export nur mit `knowledge.export` (Inhaber/Admins, nicht in Support-Sitzungen), 20 pro Person in 10 Minuten (Redis), höchstens 2.000 Dokumente, Audit-Eintrag mit IP und Browser |
| ZIP-Pfade (Zip Slip)           | Dateinamen ohne `/`, `\`, Steuerzeichen, führende Punkte und reservierte Windows-Namen; Download-Name nur ASCII im `Content-Disposition`-Header (keine Header-Injection)         |
| Sync überschreibt Gedächtnis   | Das Gedächtnis lässt sich mit keiner Quelle verbinden (Domain-Prüfung für SharePoint, BookStack, Atera)                                                                          |
